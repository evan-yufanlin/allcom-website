# 工作流程與約定

本文件記錄與網站負責人確認之工作方式；每次開始工作前請先閱讀。

## 開發流程

1. **先討論、再實作**：新功能先在對話中分析資料、提出建議；即時規劃工具先寫規格 `docs/*-spec.md`，經確認後才寫程式。
2. **功能分支**：每項修改都在 `feature/*` 分支進行，推送後由 Vercel 產生預覽網址供確認。
3. **本地測試**：負責人無法開啟 localhost，測試後以截圖（及 PDF）傳給負責人檢視。
4. **合併到正式網站**：**只有負責人的訊息中出現「合併」字樣才合併到 `main`**（例如「合併」「OK，合併到正式網站」「是的合併」）。只回「OK」「好」等不算，須再詢問確認。
5. `main` 推送後 Vercel 自動部署正式網站（https://allcom-website.vercel.app/）。近期部署常延遲約 30～60 分鐘，可用 `gh api repos/evan-yufanlin/allcom-website/deployments` 查看是否已建立部署。

## 內容限制

- 不公開個人手機號碼，只放公司電話。
- 高晟傑不列於團隊頁。
- 業主與案名一律匿名（例：「科學園區廠房（銅鑼園區）」）；repo 為公開，文件與網站皆不得出現業主名稱或建照號碼。
- 不沿用舊 logo。

## 即時規劃工具慣例

- 計算邏輯寫成純模組 `src/lib/*.ts`，並附驗算腳本 `scripts/verify-*.ts`（`npm run verify:*`），以法規範例或實際案例核對。
- PDF 用字型為子集化檔案：新增或修改 PDF 會用到之文字檔時，加入 `scripts/pdf-font.mjs` 之 `TEXT_SOURCES` 並重新產生子集（見 `docs/backlog.md` 維護備忘）。
- 引用法規、廠商型錄須註明出處與版本；規範未明列而暫定之處須在結果中標示。
