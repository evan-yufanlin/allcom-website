# 專案機電空間檢討 規格

狀態：**草案，待負責人確認**。

範圍：建立「專案」頁面，將各即時規劃工具之檢討輸入依專案存入雲端資料庫，可分次檢討、下次自動帶回並陸續修改。
`/tools/...` 即時規劃維持公開、不需登入，行為不變；只有 `/projects/...` 需要密碼。

使用者：僅汎德內部同仁（負責人 2026.11.06 確認）。

---

## 1. 密碼管制

| 角色 | 密碼 | 可做之事 |
|---|---|---|
| 管理者 | 管理密碼（一組，存於 Vercel 環境變數，僅負責人知道） | 檢視全部專案列表；新增專案、設定或重設專案密碼、修改專案資料、刪除專案；進入任一專案 |
| 專案成員 | 專案密碼（每專案一組，由管理者設定） | 以「專案編號＋專案密碼」進入該專案；檢視、新增、修改該專案之檢討與專案資料 |

- `/projects` 首頁不列出專案名稱（避免透露業主）；只有登入頁：專案編號＋密碼，或管理密碼。
- 登入成功後，瀏覽器保存已簽章之登入憑證（HttpOnly cookie，7 天），期間不需重新輸入；可登出。同一瀏覽器可同時登入多個專案。
- 專案密碼只存雜湊值（scrypt 加鹽），不存原文；管理者重設時直接設定新密碼。
- 登入失敗同一來源連續 5 次，暫停 10 分鐘，防止猜測密碼。
- 未來改為個人帳號（方案 b）時，新增「使用者」資料表與登入頁即可；專案與檢討資料結構不變，專案密碼可保留或停用。

## 2. 資料庫

- Vercel Marketplace 之 Neon Postgres（免費方案），由負責人於 Vercel 後台安裝（步驟另附，約 5 分鐘）；連線字串自動寫入 Vercel 環境變數，不進 repo。
- 另需環境變數：`ADMIN_PASSWORD`（管理密碼）、`SESSION_SECRET`（登入憑證簽章用隨機字串）。由負責人於 Vercel 後台設定，不進 repo。
- 專案名稱、業主等資料只存於資料庫，不進 repo，符合匿名規定。

### 2.1 資料表

**projects（專案）**

| 欄位 | 說明 |
|---|---|
| code | 專案編號（唯一，例：2026-001；管理者新增時輸入） |
| name | 專案名稱 |
| site | 基地位置 |
| floors | 樓層數（文字，例：B3/12F） |
| total_area | 總樓地板面積（m²） |
| owner_staff | 負責人 |
| note | 備註 |
| password_hash | 專案密碼雜湊 |
| created_at、updated_at | 建立、修改時間 |

**project_reviews（專案檢討）**：每專案每種工具一筆。

| 欄位 | 說明 |
|---|---|
| project_code | 所屬專案 |
| tool | 工具代號（substation、water-supply、…） |
| schema_version | 輸入格式版本（工具欄位異動時據以轉換，舊資料不失效） |
| input | 輸入內容（JSON） |
| summary | 結果摘要（JSON，供專案總覽顯示，例：室內淨長、淨深、面積） |
| updated_by | 修改人（儲存時選填姓名） |
| updated_at | 修改時間 |

- 只存「輸入」；開啟時以最新工具規則重新計算，工具規則更新（例：第 1009 條）後舊專案自動套用。
- 同時編輯：儲存時比對 updated_at，若他人已先儲存，提示「此檢討已由 ○○ 於 ○○ 更新」，選擇覆蓋或重新載入。

## 3. 頁面

| 路徑 | 內容 |
|---|---|
| `/projects` | 登入頁：專案編號＋專案密碼；或管理密碼。管理者登入後顯示全部專案列表與「新增專案」 |
| `/projects/[code]` | 專案總覽：專案資料（可編輯）；各空間檢討清單——狀態（未開始／已檢討）、最後修改時間與修改人、結果摘要、「開始檢討」或「開啟」按鈕 |
| `/projects/[code]/substation` 等 | 專案內檢討：與 `/tools/...` 相同介面，自動載入已存輸入；頁首顯示專案名稱與「儲存」按鈕、修改人欄位；未儲存離開時提醒 |
| 管理者功能 | 專案列表、新增專案、修改專案資料、重設專案密碼、刪除專案（需再次確認） |

- 專案頁加 `noindex`，不列入 sitemap。
- 網站導覽列不新增項目；「即時規劃」頁底加一行「專案檢討（需密碼）」連結。

## 4. 分階段

1. **第一階段**：資料庫與登入、專案列表與新增（管理者）、專案總覽、**自設變電站**接入專案（存檔、載入、修改）。
2. **第二階段**：**給水水理計算（自來水水箱）**接入；其餘工具（消防水池、電信室、緊急發電機室、停車場通風、避雷、台電配電場所）陸續接入，每個工具各自完成輸入存檔格式與驗證。
3. **第三階段（視需要）**：專案彙整 PDF、修改歷史紀錄、複製專案、個人帳號（方案 b）。

## 5. 測試

- 本機以 Postgres 測試資料庫驗證；不連正式資料庫。
- 驗算腳本 `scripts/verify-projects.ts`：密碼雜湊與驗證、登入憑證簽章與過期、輸入存檔與載入後計算結果一致（自設變電站三列範本 10,500 × 11,030）。
- 瀏覽器實測：管理者新增專案 → 專案密碼登入 → 自設變電站修改並儲存 → 登出再登入 → 自動帶回並顯示於專案總覽；截圖傳負責人確認。

## 6. 待確認

- 專案編號格式（建議「年度-流水號」，例：2026-001，由管理者輸入）。
- 登入有效期 7 天是否合適。
